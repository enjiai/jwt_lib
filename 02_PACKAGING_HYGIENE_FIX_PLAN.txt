ISSUE #1: INCONSISTENT PACKAGE NAME DECLARATION
===============================================
Location: 
  - pyproject.toml, line 4: "enjilib-jwt-auth" (with hyphens)
  - setup.py, line 4: "enjilib-jwt-auth" (with hyphens)
  - egg-info directory: enjilib_jwt_auth.egg-info (with underscores)
  - top_level.txt: enjilib_jwt (actual module name with underscores)

Description:
Python packages normalize hyphens to underscores for import names. The 
distribution name (package on PyPI/pip) uses "enjilib-jwt-auth", but the 
importable module name is "enjilib_jwt". This is CORRECT by PEP 503 standards,
but the discrepancy is worth documenting.

Expected Behavior:
  - Distribution name: enjilib-jwt-auth (correct ✓)
  - Import name: enjilib_jwt (correct ✓)
  - egg-info directory: enjilib_jwt_auth.egg-info (correct ✓)

Resolution: NO ACTION REQUIRED - This is expected. The directory naming 
            enjilib_jwt_auth vs import name enjilib_jwt is a pre-existing 
            architectural decision. Document for clarity.

Acceptance Criteria: Documented in this audit.

ISSUE #2: PYTEST-COV DEPENDENCY MISMATCH
=========================================
Location:
  - pyproject.toml, lines 17-19:
    dev = [
        "pytest>=7.0",
        "pytest-asyncio>=0.21.0",
        "pytest-cov>=4.0",  ← Listed in dev dependencies
    ]

  - setup.py, lines 18-20:
    "dev": [
        "pytest>=7.0",
        "pytest-asyncio>=0.21.0",
        # pytest-cov is MISSING here ← INCONSISTENCY
    ],

Description:
The pyproject.toml declares pytest-cov>=4.0 as a dev dependency, but setup.py
does NOT include pytest-cov. Since pytest is configured in pytest.ini to use
--cov (coverage reporting), this dependency is necessary for the test suite
to run successfully.

Evidence:
  - pytest.ini line 2: addopts = "--cov=enjilib_jwt --cov-report=term-missing"
  - egg-info/requires.txt correctly shows all three dependencies under [dev]
    (generated from pyproject.toml)

Resolution: ADD pytest-cov>=4.0 to setup.py dev dependencies (lines 21 after
            pytest-asyncio).

Acceptance Criteria: setup.py line ~21 must include "pytest-cov>=4.0,".
                     After fix, egg-info/requires.txt should remain consistent.

ISSUE #3: PY.TYPED MARKER FILE MISSING
======================================
Location:
  - pyproject.toml, line 30:
    [tool.setuptools.package-data]
    enjilib_jwt = ["py.typed"]

  - Actual file system: src/enjilib_jwt/py.typed does NOT exist

  - egg-info/SOURCES.txt: Does NOT list py.typed

Description:
The pyproject.toml declares py.typed in package-data (line 30), indicating
the package is PEP 561 compliant for type hints. However, the actual py.typed
marker file is missing from src/enjilib_jwt/py.typed.

This means:
  1. Type checkers (mypy, pyright, etc.) will not treat this as a typed package
  2. The declared package-data will fail to include the file during build
  3. Installed package will NOT have py.typed marker

Expected State for Type-Hinted Package:
  - src/enjilib_jwt/py.typed (empty file, presence-only marker)
  - Declared in pyproject.toml OR setup.py package_data
  - Listed in MANIFEST.in or auto-included by setuptools

Resolution: CREATE src/enjilib_jwt/py.typed as an empty file. This declares
            the package is PEP 561 compliant (contains inline type hints).

Acceptance Criteria: File src/enjilib_jwt/py.typed exists and is empty.
                     After reinstall, py.typed appears in installed package.
                     egg-info/SOURCES.txt includes py.typed.

ISSUE #4: BUILD SYSTEM DUPLICATION

  - setup.py (legacy build system)

Description:
Both pyproject.toml and setup.py are present and in sync. While this is not
strictly an error (modern tooling respects pyproject.toml first), it creates
maintenance overhead. Any change to dependencies requires updating BOTH files.

Current State:
  - Dependencies are in sync between both files (except Issue #2: pytest-cov)
  - pyproject.toml is the authoritative source for modern tools
  - setup.py is still read by legacy build systems and some integration tools

Resolution: RECOMMENDED (not required for immediate fix):
            Keep setup.py for legacy compatibility but mark it as deprecated.
            Add a comment at the top of setup.py directing maintainers to
            edit pyproject.toml instead.

Immediate Fix: Add comment to setup.py:

    Setup configuration for enjilib-jwt-auth package.
    
    NOTE: This file is provided for legacy compatibility only.
    For new updates, edit pyproject.toml instead (PEP 517/518 standard).
    """

Acceptance Criteria: setup.py has deprecation notice at top. Maintainers
                     prefer pyproject.toml for future edits.

        "Programming Language :: Python :: 3.11",
        "Topic :: Software Development :: Libraries",
    ]

Acceptance Criteria: pyproject.toml includes [project.classifiers] section.
                     Values match setup.py classifiers.

SINGLE SOURCE OF TRUTH STRATEGY
================================================================================

Current State:
  Two files declare the same metadata (pyproject.toml + setup.py).
  This creates a "dual source of truth" problem:
  - One truth must be canonical
  - Changes to one file could diverge from the other
  - Maintainers might edit the wrong file

Recommendation:
  ✓ CANONICAL: pyproject.toml (PEP 517/518 modern standard)
  ✗ LEGACY: setup.py (keep for compatibility, mark deprecated)

Rules Going Forward:
  1. For any dependency change: Edit pyproject.toml FIRST
  2. For any version change: Edit pyproject.toml FIRST
  3. Copy non-critical metadata (classifiers, etc.) to setup.py
  4. setup.py reads pyproject.toml values where practical
  5. Consider removing setup.py when minimum Python version reaches 3.10+
