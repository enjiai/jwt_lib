ISSUE #1: README.md — Token Example Missing 'enc' Field
────────────────────────────────────────────────────────
Location:    README.md, lines 129-140
Severity:    CRITICAL (contract misrepresentation)
Current:     
```json
{
  "sub": "user@example.com",
  "user_id": 123,
  "type": "access",
  "exp": 1706569200,
  "rand_str": "uuid",
  "roles": ["admin", "editor"],
  "permissions": ["read", "write", "delete"]
}
```

Problem:     
  • This is INCORRECT. Tokens from enji-auth ALWAYS have an 'enc' field
  • The 'enc' field contains encrypted sensitive claims (AES-GCM encrypted)
  • Code: authenticator.py:49-50 checks "if 'enc' not in public: return None"
  • Test: test_verify_extract.py:94-109 confirms missing 'enc' returns None
  • Developers following this example will create broken tokens

Impact:      
  • Users will try to issue tokens without 'enc' and get None on verify
  • False expectation that token payload is plaintext
  • Misunderstanding of security architecture (payload encryption)

Fix:         
  Replace with ACTUAL token structure that includes 'enc':

  "README.md" line 130-140 (JWT Token Structure section):
  
  Replace:
  {
    "sub": "user@example.com",
    "user_id": 123,
    "type": "access",
    "exp": 1706569200,
    "rand_str": "uuid",
    "roles": ["admin", "editor"],
    "permissions": ["read", "write", "delete"]
  }
  
  With:
  {
    "exp": 1706569200,
    "type": "access",
    "enc": "base64url-encoded-encrypted-payload-from-aes-gcm"
  }
  
  And add a NEW subsection explaining:
  
  ### Payload Structure (Inside 'enc')
  
  The 'enc' field contains encrypted sensitive claims. When decrypted by 
  verify_and_extract(), the payload contains:
  
  ```json
  {
    "sub": "user@example.com",
    "user_id": 123,
    "rand_str": "uuid",
    "roles": ["admin", "editor"],
    "permissions": ["read", "write", "delete"],
    "disallows": [],
    "employee_id": 321
  }
  ```
  
  **Note:** The actual token from enji-auth will have the above fields 
  encrypted in the 'enc' claim, NOT as plaintext JWT fields. Only 'exp' and 
  'type' are in the JWT header; everything else is in the encrypted payload.

Acceptance:  
  ✓ README.md shows 'enc' field in token example
  ✓ README.md includes explanation of plaintext vs. encrypted fields
  ✓ README.md clarifies which fields are encrypted vs. unencrypted

ISSUE #5: authenticator.py — Docstrings Correct but Scattered
──────────────────────────────────────────────────────────────
Location:    authenticator.py, lines 28-50 (verify_and_extract docstring)
Severity:    LOW (code is correct, but could be amplified in docs)
Current:     verify_and_extract() docstring describes 'enc' field:
             "Decrypt sensitive claims, and extract them"
             But doesn't mention that MISSING 'enc' returns None

Problem:     
  • Docstring doesn't explain why token might return None
  • New developers may not understand the 'enc' requirement
  • The check "if 'enc' not in public: return None" is hidden

Fix:         
  Enhance authenticator.py verify_and_extract() docstring:
  
  FROM (lines 28-42):
  """
  Verify JWT token signature, decrypt sensitive claims, and extract them.

  Args:
      token: JWT token string

  Returns:
      JWTClaims if token is valid, None if invalid
  
  Example:
      authenticator = JWTAuthenticator("secret_key")
      claims = authenticator.verify_and_extract(token)
      if claims:
          print(f"User: {claims.email}")
          print(f"Roles: {claims.roles}")
  """
  
  TO:
  """
  Verify JWT token signature, decrypt sensitive claims, and extract them.
  
  The token MUST contain an 'enc' claim with encrypted sensitive data (AES-GCM).
  See enji-auth for token minting. Tokens without 'enc' return None.

  Args:
      token: JWT token string (must include 'enc' field with encrypted payload)

  Returns:
      JWTClaims if token is valid and contains 'enc' claim, None otherwise
      
  Returns None if:
      - Token signature is invalid or uses wrong secret
      - Token is expired
      - 'enc' field is missing from JWT
      - 'enc' field cannot be decrypted (wrong secret or corrupted)
      - Token structure is malformed
  
  Example:
      authenticator = JWTAuthenticator("secret_key")
      claims = authenticator.verify_and_extract(token)
      if claims:
          print(f"User: {claims.email}")
          print(f"Roles: {claims.roles}")
      else:
          # Token was invalid, expired, missing 'enc', or decrypt failed
          raise HTTPException(status_code=401)
  """

Acceptance:  
  ✓ Docstring mentions 'enc' requirement
  ✓ Docstring explains all reasons for None return
  ✓ Developers understand this is not optional
